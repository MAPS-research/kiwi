What is this?

A Kiwi App is your own web page that Kiwi loads in an <iframe>. It talks to Kiwi only through the window bridge, wrapped by @kiwi/app-sdk. Your app never calls the Kiwi backend directly — data/LLM ops (kiwi.documentChunks, kiwi.contextualChat) are proxied by the host, which makes the real call with the app token. So no token, no CORS, no backend URL in your app. Click the buttons and watch the Event Log on the right.

1Say hello
kiwi.ready() → the host replies with live context.
2Call ops
await kiwi.documentChunks(…) — the host proxies it and returns the data.
3Use the AI
kiwi.askAI() streams an answer via the user's session.
Simulator mode is ON. You opened this file directly (not inside Kiwi), so the SDK fakes every reply locally — context, AI stream, and op responses — so you can explore offline. To run for real, register + enable the app in a class (see the README), then open it from a class tab. Toggle mode with the pill in the top bar.

Contextual study coach

ophost-proxied

await kiwi.contextualChat({ promptId, contextRequest, outputSchema }). Kiwi assembles the student's private learning context server-side and runs your admin-approved prompt — your app gets back only the model output. The op needs llm:prompt:<id> + context:student_learning:read.

4 · Drive Kiwi's UI

Navigate & chat layout

no token

kiwi.navigate(…) moves Kiwi (restricted to the current class), and kiwi.setChatDisplayMode(mode) changes where Kiwi's chat panel sits.

Both calls are acked — the host replies kiwi:ack {ok, error?}, so you can tell "done" from "silently ignored". Try the two failure buttons.
