## How to read a component chapter

1. Start with **Purpose**, **Use when**, and **Avoid when**.
2. Choose a variant from its semantic role, not its appearance.
3. Check disabled, processing, error, overflow, responsive, and focus behavior.
4. Treat stories as executable evidence and the source component as final behavior.

## AI and automation

AI agents should begin with the [machine-readable design-system catalog](./design-system/catalog.json), select either the `storybookGuide` or `kiwiDesignSystem` scope, then open only the referenced `docSource`, `storySource`, and `componentSource` files. The catalog is the single source for contract lists — docs pages render from it — while executable stories and implementation remain the behavioral evidence.

Evidence priority: {designSystem.evidencePriority.join(' → ')}.

## Definition of done

- Use semantic tokens and existing components.
- Preserve keyboard navigation, visible focus, contrast, and meaningful heading order.
- Cover important variants and states with stories.
- Verify representative desktop and narrow viewports.
- Run Storybook accessibility and interaction checks before publishing.
