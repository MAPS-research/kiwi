# Kiwi UI

React 19 + TypeScript single-page app for the Kiwi learning platform, built with
Vite. The UI uses Material UI 7 for most screens, plus Tailwind CSS 4 and
shadcn/Base UI components (`src/components/ui/`).

Institution branding (name, logo, support address, SSO domain, consent document)
is configured entirely through `VITE_*` environment variables — see
`src/config/branding.ts` and `.env.example`. A fresh checkout runs unbranded.

Kiwi UI is a client of the Kiwi backend (NestJS, port 3000). Everything under
`src/services/` is generated from that backend's OpenAPI spec — see
[API services](#api-services).

## Getting started

`.nvmrc` pins Node.js 24.21.0, which CI also uses.

```bash
nvm install   # once, if you don't have the pinned version
nvm use
npm install
cp .env.example .env
npm start     # dev server on http://localhost:3001
```

### Environment

Only variables prefixed with `VITE_` reach browser code (through
`import.meta.env`), and their values are baked in when the app is built.
`.env.example` lists all of them with defaults that work against a local backend.

| Variable | Read by | Purpose |
| --- | --- | --- |
| `VITE_BASE_PATH` | `src/utils/api.ts` | Base URL for every generated API client. Falls back to `http://localhost:3000`. |
| `VITE_BACKEND_URL` | `src/components/GoogleLoginButton` | Backend origin used to start the Google sign-in redirect. Falls back to `http://localhost:3000`. |
| `VITE_DISABLE_PASSWORD_LOGIN` | `src/config/branding.ts` | Password login is on by default. Set `true` to hide it. |
| `VITE_ENABLE_GOOGLE_LOGIN` | `src/config/branding.ts` | Set `true` to show "Continue with Google". The backend also needs `GOOGLE_CLIENT_ID`. |
| `VITE_INSTITUTION_NAME` | `src/config/branding.ts` | Institution name shown next to "Kiwi". Empty shows plain "Kiwi". |
| `VITE_SUPPORT_EMAIL` | `src/config/branding.ts` | Support address shown to users. Empty hides support prompts. |
| `VITE_SSO_EMAIL_DOMAIN` | `src/config/branding.ts` | Email domain (e.g. `example.edu`) whose accounts sign in with Google. Used only by Admin → User Management, which whitelists those accounts for Google instead of giving them passwords. |
| `VITE_LOGO_URL` | `src/config/branding.ts` | Square logo image. Defaults to `/assets/images/kiwi-mark.svg`. |
| `VITE_LOGO_LIGHT_URL` | `src/config/branding.ts` | Wordmark for the nav and sign-in panel. It is rendered as a CSS mask, so only its shape matters. Defaults to `/assets/images/kiwi-logo.svg`. |
| `VITE_CONSENT_FORM_URL` | `src/config/branding.ts` | URL of a consent document (PDF). When set, users must accept it before using the app; when empty, there is no consent gate. |

If you disable password login without enabling Google, nobody can sign in; the
login page shows a warning saying so.

Self-service sign-up exists only through Google. With Google disabled, the
register page tells visitors that accounts are created by an administrator
(Admin → User Management).

The dev server port (3001) is set in `vite.config.ts`, not by an env var.

The backend accepts cross-origin requests only from the origins listed in its
`FRONTEND_URL`, so `http://localhost:3001` must appear there or every API call
fails CORS.

## API services

`src/services/` is generated by OpenAPI Generator (`@openapitools/openapi-generator-cli`,
generator version pinned in `openapitools.json`) from the backend's live spec at
`http://localhost:3000/docs-json`. The generator is a Java program, so you need a
Java runtime. Start the backend first, then:

```bash
npm run generate-openapi
```

**Never edit `src/services/` by hand** — regenerate instead. After any backend
controller or DTO change, regenerate here so the typed client stays in sync.

## Design system

Shared UI patterns — the admin page shell and header, theme, typography, buttons —
are documented as live Storybook stories in `.storybook/stories/`. Run `npm run storybook`
and read the autodocs there; they are the source of truth for these patterns.

### Typography: Montserrat only

[Montserrat](https://fonts.google.com/specimen/Montserrat) is the single typeface
for ordinary product UI — body text, headings, buttons, forms, navigation, and
everything inheriting the MUI theme. Both font stacks that matter are literally
`'Montserrat', sans-serif`: `typography.fontFamily` in `src/Theme.ts` and `body`
in `src/index.css`. `sans-serif` is a generic fallback for glyphs Montserrat does
not cover (e.g. CJK), not an alternative UI font.

**How it loads.** The font is self-hosted from the `@fontsource-variable/montserrat`
npm package. `src/fonts/montserrat.css` re-declares the package's faces under the
plain family name `Montserrat`; `src/index.css` imports it, so the app entry and
the Storybook preview (which both import `src/index.css`) load it exactly once.
Vite emits the woff2 files into `dist/assets/`, so there is **no runtime request
to fonts.googleapis.com or fonts.gstatic.com**. One variable file per subset
covers weights 100–900, including the 300/400/500/600/700 the UI uses, plus
italics. To upgrade, bump the package and regenerate `src/fonts/montserrat.css`
as its header comment describes.

**Allowed exceptions.** Do not use another named UI font. A different font is only
acceptable where it carries meaning: math (KaTeX/MathJax), monospace for code,
commands, IDs, and JSON, the Ace editor, icon fonts (slick), SVG icons, HTML email
templates, and third-party component internals (e.g. the PDF viewer). Prefer the
`monospace` generic over naming a specific mono face, and never mark ordinary prose
as monospace.

**External Kiwi Apps.** `public/kiwi-design-tokens.css` exposes `--kiwi-font-family`,
which now names only Montserrat. That file ships tokens, not `@font-face` rules, so
an embedded app must load Montserrat itself. With a bundler, install
`@fontsource-variable/montserrat` and mirror the `@font-face` aliases in
`src/fonts/montserrat.css`; importing the package's root stylesheet alone names
the family `Montserrat Variable`, which does not match this token. A build-less
app can instead link Google Fonts. See [KIWI-APPS.md](KIWI-APPS.md).

`src/fonts/montserrat.test.ts` and `src/typography.test.ts` fail the build if a
different ordinary-UI font creeps back into the theme, global CSS, design tokens,
or Storybook guidance.

## Building for production

```bash
npm run build
```

This writes static files to `dist/`. `VITE_*` values are read at build time, so
set them (in `.env` or the build environment) before building, and rebuild when
they change. `vite build` does not type-check; run `npx tsc --noEmit` if you want
that.

Serve `dist/` from any static host. The app is built for the site root (no
`base` is set in `vite.config.ts`) and uses client-side routing, so configure the
host to fall back to `index.html` for unknown paths.

CI (`.github/workflows/ci.yml` at the repository root) builds the app on every
push and pull request; the unit tests run there but do not fail the build. This
repository has no deploy workflow.
